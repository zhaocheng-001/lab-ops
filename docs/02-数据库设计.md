## 四、设计要点

### 4.1 工单状态机一致性

通过数据库层约束 + 应用层状态转移校验：
```python
@action(detail=True, methods=["post"], url_path="start")
def start(self, request, pk=None):
    order = self.get_object()
    if order.status not in (MaintenanceOrder.Status.PENDING,
                            MaintenanceOrder.Status.PROCESSING):
        return _err("当前状态不允许开始")
    ...
```

### 4.2 冗余字段

- `reporter_name` / `handler_name` / `dispatcher_name` / `responsible_name` 冗余到工单 / 报修表，避免 N+1 查询。
- `laboratory_id` 在 `FaultReport` 上冗余（虽然能从 device 推导），便于按实验室过滤的列表查询走索引。

### 4.3 JSON 字段使用

- `images` / `checklist` / `checklist_result` 等结构化但无固定 schema 的数据使用 JSON，避免新增表带来的耦合。
- Django `JSONField` 在 MySQL 5.7+ / PostgreSQL 上原生支持。

### 4.4 软删除

用户、实验室、设备均使用 `is_active` 软删除，保留历史数据用于审计和统计分析。

## 五、迁移策略

```bash
python manage.py makemigrations          # 生成迁移文件
python manage.py migrate                 # 执行迁移
python manage.py init_demo_data          # 基础种子
python manage.py seed_maintenance_demo   # 运维种子
```

迁移文件存放在 `apps/<module>/migrations/`，与代码同步提交。
